1. Project Overview

ArgoFarm is an AI-powered agricultural advisory and crop disease diagnostics platform designed specifically for farmers in Pakistan. The platform integrates multiple artificial intelligence models — including Google Gemini 2.5 Flash Vision for image-based disease detection, Groq LLaMA 3.3 for conversational advisory, and a custom-trained Random Forest model for soil-based crop recommendations — to provide a comprehensive decision-support system.

The application is a full-stack web platform with a Flask-based RESTful backend, a Vanilla JavaScript single-page application (SPA) frontend built with Vite, and a MySQL/SQLite database layer. It supports bilingual (English/Urdu) interaction across all modules and is designed to be mobile-responsive for field usage by farmers.

Problem Statement

Pakistani farmers face significant crop losses due to late or incorrect disease identification, lack of access to expert agronomists, unreliable weather-based decision making, and absence of transparent wholesale market pricing. ArgoFarm addresses these challenges by providing instant AI-powered diagnostics, real-time weather advisories, community-driven knowledge sharing, and AI-assisted wholesale market analysis — all accessible through a single web interface.

Key Objectives

  • Provide instant, AI-powered crop disease detection from leaf images with actionable treatment advisories
  • Enable voice-enabled conversational farming advisory in English and Urdu
  • Deliver real-time weather forecasts with AI-generated crop protection guidance
  • Facilitate a community forum where farmers share knowledge and get AI-powered diagnosis on their posts
  • Support wholesale marketplace price analysis and negotiation tactics using AI
  • Provide soil-parameter-based crop recommendations using trained ML models

3.1 Data Flow

  1. Client Layer: The browser-based SPA sends HTTP requests to the Flask backend. All protected routes require a JWT Bearer token in the Authorization header.
  2. API Gateway: Nginx acts as a reverse proxy, forwarding /api/* requests to Flask and serving static frontend assets.
  3. Application Layer: Flask processes business logic using modular blueprints (auth, scan, chat, dashboard, etc.). Each blueprint handles route validation, authentication, and orchestration of AI/ML services.
  4. AI/ML Layer: Depending on the feature, Flask dispatches requests to Google Gemini (vision/text), Groq (chat/transcription), or the local scikit-learn pipeline. Each AI call has an offline fallback if the external API is unavailable.
  5. Data Layer: MySQL (production) or SQLite (development) stores user profiles, scan results, chat history, community posts, and marketplace listings.

6. API Rate Limiting & Security

To prevent API key misuse and respect free-tier quotas of external AI providers, ArgoFarm implements a centralized, decorator-based rate limiting system applied to all AI-powered endpoints.

6.1 Rate Limiting Architecture

AttributeDetails
ImplementationPython decorator (@rate_limit) in backend/utils/rate_limit.py
StorageIn-memory dictionary keyed by (identifier, endpoint, period)
User IdentificationPrimary: JWT user_id from token payload. Fallback: Client IP address (supports X-Forwarded-For for reverse proxies)
HTTP Response on Block429 Too Many Requests with JSON: {"status": "error", "message": "Rate limit exceeded (N req / Xm). Please wait Y seconds."}
Decorator StackingMultiple @rate_limit decorators can be stacked (e.g., per-minute AND per-day limits on the same endpoint)

7. Database Design

7.1 Database Engine

ArgoFarm uses a dual-database strategy: MySQL 8.0 for production with a 10-connection pool, and SQLite for zero-configuration local development. The application auto-detects MySQL availability at startup and falls back transparently to SQLite. All SQL queries use parameterized statements and are automatically translated between MySQL (%s) and SQLite (?) placeholder formats.

7.2 Schema Tables

10.2 Production Deployment Flow

  1. Frontend Build: npm run build → outputs to dist/ → deployed to Netlify CDN.
  2. API Proxy: Netlify _redirects file proxies /api/* to the VPS backend, avoiding mixed-content issues.
  3. Backend: Flask runs on the VPS behind Nginx. Docker Compose orchestrates MySQL + Flask + Nginx.
  4. Database: MySQL 8.0 with persistent Docker volume. Auto-initialization via init_db.py.

11. Security Measures

Security LayerImplementation
Password Storagebcrypt hashing with automatic salt generation. Passwords are never stored in plaintext.
AuthenticationJWT (JSON Web Tokens) with HS256 signing. Tokens include user_id, exp, and iat claims. 30-day expiry.
Authorization@token_required decorator validates JWT on all protected endpoints. Returns 401 on invalid/expired tokens.
Rate Limiting@rate_limit decorator prevents API abuse. Per-user (JWT) and per-IP tracking. Returns 429 with wait time.
CORSFlask-CORS configured with allowed headers (Content-Type, Authorization) and methods.
SQL Injection PreventionAll database queries use parameterized statements (%s / ? placeholders). No string concatenation in queries.
API Key ProtectionAll external API keys (Gemini, Groq, Gmail) stored in .env file, never committed to version control.
Input ValidationAll endpoints validate required fields and return 400 Bad Request with descriptive messages on invalid input.
Image ValidationUploaded images are validated for non-empty content before processing. Non-plant images are rejected by AI.
Session SecurityFrontend auto-clears auth tokens and cached data on 401 responses or manual logout.
